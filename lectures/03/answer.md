## 演習

- 第1回（素のLLM）とエージェントの回答の違い：第1回の素の LLM は、宿題の3レベルを「初級・中級・上級」のような一般的な難易度と推測し、「レベル1は全員必須」とも述べていました。エージェントは用語集を確認して「基礎（講義内容の確認）・実装（自分でコードを書く）・発展（調査や試行）」と答え、「どれか1つで完了」「原則として採点なし」も実際の決まりと一致しました。
- `--trace` で見えたツール呼び出し（ツール名と引数）：「LoRAとQLoRAの違いは？」では `search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回です。「第2回の復習問題を1問出して」では `make_quiz({'lecture': 2})` の1回です。
- 1つの質問での LLM 呼び出し回数（`requests`）：上の2問とも `requests=2` でした（LoRA の質問は `tool_calls=2`、復習問題は `tool_calls=1`）。ツールを呼ぶと決める1回と、結果を見て回答する1回で、2つの検索は1回の応答でまとめて呼ばれていました。
- 追加したツールと、docstring に書いた説明：`make_quiz(lecture: int)` を追加しました。docstring には「指定した回（1始まりの整数）の用語から復習問題を1問作り、問題と答えを返す。『第2回の復習問題を出して』のように、復習問題やクイズを頼まれたときに使う。」と書きました。該当する用語がない回では、問題を作れないことを文章で返します。`uv run pytest -q` は11件成功しました。

## 宿題

- 取り組んだレベル：発展（a）ADK で作り直す
- やったこと：`adk_agent/glossary_agent/agent.py` に、演習と同じ `INSTRUCTIONS` と3つのツール（`search_glossary`、`get_lecture_summary`、`make_quiz`）を渡す `root_agent` を作りました。ADK 2.14.0 を `uv run --with google-adk` で一時的に足し、`adk run` で演習と同じ3問を聞いて、Pydantic AI 版と比べました。コードの下書きには Claude Code を使い、実行と出力の確認は自分で行いました。
- 結果：

  書き方の違いは次のとおりです。

  | 観点 | Pydantic AI | ADK |
  |---|---|---|
  | 指示 | `Agent(instructions=INSTRUCTIONS)` | `Agent(instruction=INSTRUCTIONS)` |
  | ツール | `agent.tool_plain(関数)` で1つずつ登録 | `tools=[関数, ...]` で一覧を渡す |
  | モデル | 実行時に `run_sync(..., model=...)` で渡す | 定義時に `model="gemini-3.5-flash-lite"` と書く |
  | 名前 | 不要 | `name="glossary_agent"` を指定 |
  | 実行の仕組み | CLI は `app/agent.py` に自分で書く | `adk run` が対話の画面を提供 |
  | ツール呼び出しの確認 | 自作の `--trace` で表示 | `adk run` の画面には表示されない |

  回答の比較は次のとおりです（各1回の実行）。

  | 質問 | Pydantic AI | ADK |
  |---|---|---|
  | 宿題の3レベル | 基礎・実装・発展を正しく回答。末尾は「（第1回）」 | 内容は同じ。末尾は「（関連回：第1回）」 |
  | LoRA と QLoRA の違い | 用語集の定義に沿って両者を説明。末尾は「関係する回：第2回」 | 同じ内容を「重みの扱い方の違い」と要約してから説明。末尾は「（関連回：第2回）」 |
  | 第2回の復習問題 | 「量子化」を出題し、答えを促す | 「事前学習」を出題し、自分で確認するよう促す |

  どちらも答えは伏せて問題だけを示しました。「量子化」「事前学習」はどちらも用語集で第2回の用語です。

- 気づき・疑問：
  - 指示とツールが同じなら、組み立てる部品が変わっても、回答の内容はほぼ同じでした。差が出たのは言い回しと末尾の書き方で、復習問題の違いは `make_quiz` が `random.choice` で用語を選ぶためと考えられます。各1回の実行なので、フレームワークによる品質の差があるとは言えません。
  - 条件が完全に同じではない点もあります。`app.agent` は1問ごとに別のプロセスで動きますが、`adk run` は3問を同じセッションで続けて聞いたので、2問目以降は前の会話が残っていた可能性があります。
  - ADK は対話の画面をすぐ使えるのが便利です。一方、`adk run` の画面だけではどのツールが呼ばれたか分からないので、評価や不具合の調査にはログやトレースの確認方法を別に用意する必要があると感じました。
  - 疑問：ADK で Pydantic AI の `--trace` に相当する情報を残すには、イベントを読むコードを書くのと Web UI（`adk web`）を使うのとでは、どちらが一般的なのでしょうか。
